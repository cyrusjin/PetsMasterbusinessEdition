# 商家订阅、7 天试用与兑换码：服务端实施说明

小程序端已经接入下列 `storeService` actions。试用资格、访问权限、支付回调和兑换码核销必须由服务端原子校验；前端状态只能用于展示，不能作为权限依据。

## 产品规则

| 状态 | 可用范围 | 价格 | 有效期 |
| --- | --- | ---: | --- |
| 上线前老用户限免 | 全部平台功能 | 免费 | 至 2026-09-10 当天结束 |
| 新用户试用 | 全部平台功能 | 免费 | 注册成功起 7 天 |
| 月付会员 | 全部平台功能 | ¥19.9 | 1 个自然月 |
| 半年付会员 | 全部平台功能 | ¥99（原价 ¥119.4） | 6 个自然月 |
| 年付会员 | 全部平台功能 | ¥169（原价 ¥238.8） | 1 年 |
| 试用或会员已到期 | 仅允许登录、查看订阅页和完成支付 | - | - |

会员只按使用时长计费，不按在住宠物数量、订单数量或经营规模区分，也不存在永久免费的基础版。旧的 `basicPetLimit`、`currentPetLimit`、`freeDogLimit` 和 `unlimited` 字段及相关额度校验应停止使用。

## 上线时老用户迁移

服务端部署时固定记录 `membership_rollout_at`。所有在该时间之前已经注册成功的历史门店，一律发放老用户限免权益：

```text
migration_started_at = membership_rollout_at
migration_expires_at = 2026-09-11 00:00:00 Asia/Shanghai
migration_granted_once = true
```

即老用户可以完整使用到 **2026 年 9 月 10 日 23:59:59（北京时间）**，9 月 11 日零点起需要付费、有效推广权益或其他仍生效的授权。迁移任务必须幂等，可按 `store_id + entitlement_type=migration_20260910` 建唯一索引，重复部署不得重复或延长权益。

已经付费且会员到期时间晚于该日期的用户，保留更晚的付费到期时间。最终访问权限取所有有效权益的并集。

## 新用户 7 天试用

在门店注册/入驻成功的同一数据库事务中写入试用资格：

```text
trial_started_at = registration_completed_at
trial_expires_at = registration_completed_at + 7 days
trial_granted_once = true
```

- 同一门店及同一主体只能自动领取一次，重复提交注册、重新登录或重新安装小程序都不能重置试用期。
- 如果入驻流程需要审核，以“审核通过并首次创建可用门店”的时间作为注册成功时间。
- 已付费用户的访问权限取付费订阅与试用期的并集；购买会员不能缩短当前有效期。
- `registered_at >= membership_rollout_at` 的新用户只发放 7 天试用，不再获得老用户限免权益。

服务端必须用当前时间实时计算：

```text
trial_active = now < trial_expires_at
subscription_active = now < subscription_expires_at
migration_active = now < migration_expires_at
promotion_active = exists(active promotion entitlement where now < expires_at)
access_active = trial_active OR subscription_active OR migration_active OR promotion_active
```

不要依赖定时任务修改状态。`trialDaysRemaining` 建议向上取整，且不得返回负数。

## 全平台访问控制

除登录、注册/入驻、获取会员状态、创建支付、查询支付结果、兑换码、推广任务查询/截图上传/提交审核和必要客服接口外，所有商家端业务 action 都必须在服务端统一经过授权中间件：

```text
allow when trial_active OR subscription_active OR migration_active OR promotion_active
otherwise return MEMBERSHIP_REQUIRED
```

到期后应禁止创建或修改订单、确认到店、客户管理、日常记录、统计、账本及门店配置等业务操作，不再根据在住宠物数量决定是否放行。只在某几个订单入口校验是不完整的，也不能依赖客户端隐藏按钮。

小程序进入商家经营端时，应先读取会员状态。确认所有权益均已到期后直接 `reLaunch` 到带 `required=1` 的订阅会员页，不展示可取消的提示框；任一业务接口返回 `MEMBERSHIP_REQUIRED` 时也执行相同跳转。强制订阅模式必须调用 `wx.hideHomeButton()` 隐藏左上角主页入口，且不能提供“切换用户版”按钮；支付成功后再 `reLaunch` 回商家经营端。订阅页、支付、兑换码和推广任务页面必须保持可访问。

## 下单与支付

- `storeService.createMembershipPay`：请求 `{ store_id, plan_code }`，`plan_code` 为 `pro_monthly`、`pro_half_yearly` 或 `pro_yearly`。
- 金额只能从服务端套餐配置读取，禁止信任客户端显示金额：月付 `1990` 分、半年付 `9900` 分、年付 `16900` 分。
- `originalPriceYuan` 只用于划线展示，不参与下单或支付金额计算。
- 返回 `{ success, order_id, payment }`，`payment` 为 `wx.requestPayment` 所需参数。
- `storeService.queryMembershipPay`：请求 `{ order_id }`，仅允许查询当前用户有权管理的门店订单。
- 微信支付回调验签后，以支付单号做幂等键。若已有未过期的付费订阅，从原 `subscription_expires_at` 顺延；否则从支付成功时间起算。试用期不累加到付费订阅时长。

## 推广任务与官网人工审核

推广任务不能写死在小程序里，也不能由用户自行领取奖励。小程序只负责读取官网已发布任务、上传截图和提交审核记录。官网管理后台新增一级菜单或会员模块子菜单 **“推广中心”**，包含“任务管理”和“提交审核”两个页面。

### 官网任务管理与发布

任务表建议包含：

```text
id, code, title, description, requirement_text, reward_days,
status=draft|published|paused, starts_at, ends_at, sort_order,
submission_limit, allow_resubmit_after_reject,
created_at, created_by, updated_at, updated_by, published_at
```

后台任务管理支持新增、编辑、预览、发布、暂停和排序。接口建议：

- `admin.listPromotionTasks`：按状态查询全部任务。
- `admin.createPromotionTask`：创建草稿。
- `admin.updatePromotionTask`：仅修改草稿或已暂停任务；已产生提交记录后不得修改 `code`。
- `admin.publishPromotionTask`：校验标题、任务说明、截图要求、奖励天数和有效期后发布。
- `admin.pausePromotionTask`：暂停后不再接受新提交，但历史审核记录继续保留。

发布和暂停必须记录管理员及操作时间。`reward_days` 必须是服务端校验后的正整数。小程序的 `getPromotionTasks` 只返回 `status=published` 且当前时间处于 `starts_at/ends_at` 有效区间的任务，并按 `sort_order` 排序；后台未发布任何任务时返回空数组。

### 小程序端接口

- `storeService.getPromotionTasks`：请求 `{ store_id }`，返回任务配置及当前门店最近一次提交状态。
- `storeService.submitPromotionProof`：请求 `{ store_id, task_code, proof_url }`，新建一条 `pending` 审核记录。
- 截图通过现有上传签名接口上传到 `promotion-proofs` 目录；服务端必须限制为图片格式、限制文件大小，并校验 URL 属于平台允许的对象存储域名。
- 试用或会员已到期的用户仍可访问这两个推广接口及截图上传签名接口，否则无法通过任务重新获得权限。
- 同一门店、同一任务同时只能有一条 `pending` 记录；`approved` 任务是否允许再次参与由任务配置决定。

提交记录建议包含：

```text
id, store_id, owner_openid, task_code, proof_url, status,
reward_days_snapshot, submitted_at, reviewed_at, reviewed_by,
review_note, entitlement_id, idempotency_key
```

`reward_days_snapshot` 在提交时从服务端任务配置复制，禁止信任客户端传入奖励时长。

### 官网管理后台“提交审核”

列表至少展示：提交时间、门店名称、联系人、任务名称、奖励天数、截图缩略图、状态和审核人，并支持按状态、任务及时间筛选。详情页支持查看原图，以及“审核通过”和“驳回”两个操作；驳回时必须填写原因。

后台接口建议：

- `admin.listPromotionSubmissions`：分页查询，默认优先显示 `pending`。
- `admin.getPromotionSubmission`：查看提交详情及历史审核记录。
- `admin.reviewPromotionSubmission`：请求 `{ submission_id, decision: "approved" | "rejected", review_note }`。

审核通过必须在同一数据库事务中：

1. 锁定提交记录并确认状态仍为 `pending`；
2. 使用提交时保存的 `reward_days_snapshot` 创建 `promotion` 类型权益；
3. 从当前有效推广权益到期时间或审核通过时间中较晚者开始顺延；
4. 写入权益流水和审核日志；
5. 将提交状态改为 `approved` 并关联 `entitlement_id`。

重复点击或接口重试必须返回同一审核结果，不能重复发放权限。驳回只修改审核状态和原因，不发放任何权益；用户可按任务规则重新提交截图。

## 兑换码

官网后台可提供批量生成兑换码：数量、会员时长、批次备注、失效时间、操作人。兑换码属于付费/商务发放的会员凭证，不提供“做任务免费领会员”的入口。

建议只存 `SHA-256(code + server_secret)`，明文只在生成后展示或导出一次。兑换事务应锁定码记录，校验未兑换、未过期及门店权限，再顺延 `subscription_expires_at` 并写入不可变流水。

## 审计与迁移

- 订阅订单、支付回调、老用户迁移、试用发放、推广审核、兑换及退款流水都应保留不可变审计记录。
- `store_id` 必须在服务端校验 owner/staff 权限；兑换建议仅 owner 操作。
- 退款后按业务规则回收对应付费有效期，但不得重新发放 7 天试用。
- 上线前删除旧的宠物额度配置和拦截文案，执行老用户迁移并核对数量，同时确认所有业务 action 都接入统一访问控制。
